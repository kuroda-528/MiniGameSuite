# 0002. 生徒はフォークから PR を出し、動作確認は手元で行う

- **日付**: 2026-10-18
- **ステータス**: 承認

## 背景

本家リポジトリ `saitokodomopg/MiniGameSuite` は Public で、`main` にマージされたものがそのまま本番に公開される。
生徒が本家に直接ブランチを push する運用だと、全員に書き込み権限を渡す必要がある。

## 決定

1. 生徒には本家の書き込み権限を渡さない。各自がフォークを作り、そこから本家の `main` へ PR を出す
2. 生徒の動作確認は手元（`npm run dev` とテスト・型チェック・lint）で行う
3. 先生は必要なら PR を手元に取ってきて確認してからマージする

## 理由

- 本家に書き込めるのが先生だけになり、うっかり `main` に push して公開してしまう事故が起きない
- テスト・型チェック・lint は生徒のパソコンだけで実行でき、確認のためにネットに公開する必要はない

## 却下した選択肢

| 選択肢 | 却下理由 |
|--------|----------|
| 生徒を collaborator にして本家にブランチを push | 全員が `main` に書き込めてしまう。プレビュー URL は出るが、権限の事故のほうが重い |

## 影響

- Workers Builds はフォークのブランチをビルドしないため、生徒の PR にプレビュー URL が出ない
  （ADR 0001 の「プレビュー URL が出るため、作った本人がすぐに確認・共有できる」は生徒の PR には当てはまらない）
- 全員が `src/games/index.ts` に1行ずつ足すため、コンフリクトが起きやすい。直し方は `src/games/README.md` に書く
- プレビュー URL が必要になったら、GitHub Actions でフォークの PR をビルドする仕組みを ADR で検討する
