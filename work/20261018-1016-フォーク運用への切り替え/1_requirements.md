# 1. Requirements — フォーク運用への切り替え

## 目的

生徒は本家リポジトリに書き込み権限を持たず、自分のフォーク（GitHub 上の自分専用コピー）から
PR を出す運用にする。そのとき迷わないよう、ルールと手順書をフォーク前提に書き直す。

## やること

- 生徒の流れを「フォーク → clone → 作業ブランチ → フォークに push → 本家へ PR → 先生がマージ」にする
- フォークからの PR ではプレビュー URL が出ないため、生徒の確認は手元（`npm run dev` とテスト・型チェック・lint）で行う
- 先生は必要なら PR を手元に取ってきて確認する（`gh pr checkout <PR番号>`）
- 本番 URL が確定したので「（Cloudflare 接続後に確定）」を消す

## 受け入れ条件

- [ ] `src/games/README.md` だけ読めば、フォークの作成から PR を出すまで迷わずできる
- [ ] プレビュー URL 前提の記述が、生徒向けの手順・PR テンプレート・ルールから消えている
- [ ] `CLAUDE.md` `docs/architecture.md` `docs/concept.md` の運用の記述が、フォーク前提でそろっている
- [ ] 運用を変えた理由が ADR として残っている

## やらないこと（スコープ外）

- GitHub のブランチ保護ルールの設定（先生が管理画面で行う）
- 完了済みの作業メモ（`work/20261018-0713-土台と10秒れんだ/`）の書き換え
- `.claude/commands/kickoff.md` の書き換え（プロジェクト開始用の汎用手順のため）
